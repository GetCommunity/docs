# Programming Principles & Values

## Be `Explicit`

**Explicit is better than implicit.**

Implied logic requires programmers to make assumptions about how the code should word. Explicit code clearly describes the logic and improves code legibility and maintainability.

## `D`on't `R`epeat `Y`ourself (DRY)

**DRY is a principle aimed at reducing repetition of software patterns, replacing it with abstractions or using data normalization to avoid redundancy.**

## Comments are for `Why`, not `What`

Document or code comments should only be used sparingly to explain the `why` the code is written in a certain way. Comments must never explain `what` the code is doing or how the code is implemented. The code should be explicit, concise, and self-explanatory.
